sqrail runs read-only SQL over CSV, TSV, JSON, and Parquet.

sqrail schema [--memory SIZE] [--threads N] [--timeout DURATION]
              [--max-input-files N] [--strict-schema] [--all-varchar] FILE...
sqrail check [-t NAME=PATH]... [--memory SIZE] [--threads N] [--timeout DURATION]
             [--max-rows N] [--max-input-files N] [--max-sql-bytes SIZE]
             [--strict-schema] [--all-varchar] [SQL|-]
sqrail run [-t NAME=PATH]... [-o FILE] [--memory SIZE] [--threads N]
           [--spill DIR [--max-spill SIZE]] [--timeout DURATION] [--max-rows N]
           [--max-output-bytes SIZE] [--max-input-files N] [--max-sql-bytes SIZE]
           [--stats] [--strict-schema] [--all-varchar] [SQL|-]
sqrail --help
sqrail --version

Names/types result: schema once. Otherwise trust stated names/types, run once, and stop after success.
-t binds file, Parquet directory, or glob; '-' reads SQL; '--' ends options.
Files union by name; --strict-schema requires exact schemas; --all-varchar keeps CSV/TSV VARCHAR.
check emits columns, inputs, and plan without execution.
No -o: JSONL stdout. -o: extension selects format; outputs: private, atomic, never overwritten.
Limits fail closed; --stats writes stderr success JSON. Text supports .gz/.zst.
SQL is one SELECT, VALUES, WITH; order needs ORDER BY.
Errors: one stderr JSON (exit: 0 ok, 2 usage, 3 input, 4 SQL, 5 output, 70 internal).

Examples:
  sqrail schema sales.csv
  sqrail run -t sales=sales.csv 'SELECT count(*) AS n FROM sales'
  sqrail run -t sales=sales.csv -o result.parquet - < query.sql
