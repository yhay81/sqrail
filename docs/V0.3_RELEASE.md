# v0.3 release gate

> **Status:** v0.3.0 was released on 2026-07-28. This document preserves the
> exact gate used for that release; it is not a current release checklist.

v0.3 raised the reliability of the existing one-query contract rather than
adding another execution mode. The release was ready to tag only when every
required gate below had reproducible evidence.

## Product scope

- evolving multi-file CSV, JSON, and Parquet schemas union by column name
- opt-in exact schema validation for `run`, `check`, and `schema`
- final-result row limits with no committed partial file
- machine-readable success statistics kept separate from stdout data
- result-column and input-count metadata from non-executing `check`
- structured cleanup after deadlines, interrupts, and closed stdout pipes
- SQL-byte, input-file, result-row, and output-byte safety caps
- owner-only POSIX modes and protected current-user Windows ACLs
- versioned machine-readable diagnostics, schema, plan, and statistics objects

Natural-language input, configuration files, persistent databases, arbitrary
extensions, and an operating-system sandbox remain out of scope.

## Required gates

| Area            | Gate                                                                                                                                            | Evidence                               |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Contract        | `--agent-help`, README, site, and `docs/CONTRACT.md` agree                                                                                      | smoke assertions and review            |
| Correctness     | parser units, JSON units, evaluator units, and end-to-end formats pass                                                                          | `cmake --workflow --preset release`    |
| Memory safety   | frontend and embedded DuckDB pass ASan/UBSan and ThreadSanitizer                                                                                | `sanitize` and `thread` workflows      |
| Static quality  | format and Clang-Tidy are clean with warnings as errors                                                                                         | `cmake --workflow --preset strict`     |
| Parser boundary | strict JSON and CLI parsing fuzz for at least 30 seconds each                                                                                   | fuzz preset and committed dictionaries |
| Portability     | bundled builds pass on Linux, macOS, and Windows, x86-64 and Arm64; system DuckDB passes on Linux/macOS                                         | six-lane CI matrix                     |
| Packaging       | installed executable, contract, licences, corpus, runner, oracle, and evaluator are present                                                     | release workflow package checks        |
| Supply chain    | signed annotated tag, reproducible archive, SPDX SBOM, SHA-256 manifest, provenance and SBOM attestations                                       | tag workflow                           |
| Safety          | no-overwrite race, row-limit cleanup, SIGPIPE, SIGINT/SIGTERM, spill isolation, and private modes pass                                          | smoke test                             |
| Performance     | every matrix output matches DuckDB row count and checksum; CPU, RSS, output bytes, cache state, binary hashes, and host provenance are recorded | benchmark harness                      |
| Agent use       | five paired independent repetitions per model, arm, and task pass the artifact-backed acceptance gate                                           | `benchmarks/agent-eval.py` report      |

The agent-use gate requires real independent model sessions. Synthetic or
replayed successes are not release evidence. `agent-run.py` must create each
randomized workspace and execute shell-free command plans. `agent-eval.py`
must then recompute every oracle from the raw stdout, stderr, output file,
workspace snapshots, dataset, pinned binaries, and their digests. Raw JSONL,
artifacts, exact help text, corpus digest, model identifier, and evaluator
report must be retained together.

## Release sequence

1. Run release, strict, sanitizer, ThreadSanitizer, both fuzz targets, Windows
   presets, and system-provider workflows from a clean checkout.
2. Run the startup benchmark and the 12-case workload matrix against the pinned
   DuckDB revision.
3. Run the twelve-task agent evaluation and archive the raw recording.
4. Confirm `CHANGELOG.md`, version output, site copy, and tag all say `0.3.0`.
5. Confirm the repository's GitHub immutable-releases setting is enabled.
6. Create an annotated, signed release tag only after the cross-platform CI
   matrix passes.

The tag-triggered workflow then rebuilds six deterministic archives, verifies
the tag signature and binary version, strips Unix executables, checks runtime
linkage and installed contents, emits external and embedded SPDX SBOMs,
publishes SHA-256 checksums, and attaches build-provenance and SBOM
attestations. It creates a draft release, attaches the complete asset set,
publishes it, and fails unless GitHub verifies the resulting release as
immutable.
